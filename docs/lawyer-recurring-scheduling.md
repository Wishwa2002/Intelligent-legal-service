# Lawyer recurring scheduling refactor

## Existing model inspected

LawyerAvailability stored a dated working interval. AvailabilitySlot stored explicit child times and IsBooked. Appointment retained its time only through SlotId → AvailabilitySlot → LawyerAvailability.Date. The booking service even provisioned four afternoon slots on demand when no availability existed. Search, recommendation date filtering and workforce capacity depended on explicit records. Lawyer creation had no weekly schedule or leave controls. Requested, Confirmed, Rescheduled and Completed appointments occupied time; Cancelled and Rejected released it. Existing overlap checking already used half-open intervals.

## Source of truth and migration

Availability now derives from LawyerWorkingSchedule (one unique row per lawyer and weekday), LawyerUnavailability, blocking Appointment intervals and office-local current time. Lawyer.DefaultAppointmentDurationMinutes defaults to 30, validated from 15 through 240. All dates and times use the configured Scheduling:TimeZone (default Asia/Colombo).

Legacy dated availability and slots remain to preserve appointment history. They no longer contribute available capacity, even when IsBooked is false. A new appointment creates exactly one timing snapshot in these tables; availability reads only snapshots linked to blocking appointments. Opaque derived slot IDs allow existing Guid booking request contracts to stay compatible and are revalidated inside a transaction. Legacy IDs may still be submitted if their interval satisfies the new schedule.

The additive migration creates schedules/leave and indexes without deleting old data. Existing dated windows are conservatively converted per weekday using their common overlap; incompatible or missing days are off. This is a migration starting point requiring Admin review, not a claim that historical hours are the lawyer's permanent preference. New-lawyer UI defaults Mon–Fri 09:00–17:00 and weekends off; the saved form determines the schedule. API callers omitting a schedule receive off days.

## Calculation and concurrency

Generate duration-sized slots entirely inside a working window. Exclude past starts, leave and appointments whenever existing.Start < candidate.End && existing.End > candidate.Start. Adjacent intervals remain available. Cancelled/Rejected do not block; all other existing statuses block conservatively.

PostgreSQL mutations lock the selected lawyer row with FOR UPDATE inside a transaction before reading availability. Booking, rescheduling, schedule changes and leave management use the same lock. Recommendation approval retains its existing serializable workflow transaction. A stale slot returns 409; leave conflicts return appointment IDs, dates and times. Schedule changes that strand future appointments also return 409. No appointment is automatically cancelled.

Capacity batch-loads lawyers, weekly schedules, leave and appointment intervals in four queries for the configured future window. Recommendation uses the same system calculation; Gemini receives no weekly schedules or leave records and remains responsible only for legal interpretation. No-date recommendations retain Availability Not Filtered.

4. **Entities.** `LawyerWorkingSchedule`: Guid ID/lawyer ID, numeric weekday 0–6, working flag, TimeOnly start/end, UTC audits. `LawyerUnavailability`: Guid ID/lawyer ID, office-local timestamp boundaries, reason, full-day flag, UTC audits. Duration lives on Lawyer; one window per day is intentionally supported.
5. **Source of truth.** Recurring schedule + leave + blocking appointment intervals + current office time + duration. All bookable times and capacity use `AvailabilityService`.
6. **Legacy strategy.** Preserve and deprecate explicit availability as a booking source. The migration conservatively derives common per-weekday hours from legacy dated windows. Missing/incompatible days are off until an Admin reviews them. Old IDs remain accepted only when their actual interval passes the new rules. Actual bookings create one immutable timing snapshot rather than future inventory.
7. **Slot algorithm.** Generate duration-sized intervals fully inside working hours, then remove past starts, leave overlaps and occupied intervals. Return deterministic opaque Guid IDs, date, working-day flag, duration, timezone and an empty-state reason. Reads create no database rows. Only an actual booking/reschedule persists an appointment timing snapshot.
8. **Overlap.** Half-open intervals: `existing.Start < requested.End && existing.End > requested.Start`. Partial overlaps block; touching endpoints do not. Schedule uniqueness is enforced by `(LawyerId, DayOfWeek)` and database constraints.
9. **Statuses.** Requested, Confirmed, Rescheduled and Completed occupy time, matching the existing service. Cancelled and Rejected do not. Other status values conservatively block. Legacy `IsBooked` alone is not an availability decision.
10. **Recommendation integration.** Keep the existing classification and recorded-experience ranking rules. Python receives controlled derived `availableDates`; Gemini receives the legal requirement/catalog, not schedules or leave. The backend independently rechecks returned lawyers and requested dates. No-date results explicitly say Availability Not Filtered. Dates inferred beyond the initial one-year snapshot are evaluated as one actual day and use the identical experience/stable-ID ranking, avoiding a false no-match result. Explicit preferred dates also use their actual day.
11. **Workforce integration.** Four bounded queries load all lawyers, schedules, overlapping leave and appointments for the configured calendar window. Count generated free intervals in memory; sum eligible single-Practice-Area active lawyers. Both Workforce Intelligence and the module summary use this calculation. The default window contains the remaining times today plus the following 29 dates. Workforce demo scenarios now configure weekly schedules, preserving their existing isolated `[Demo]` catalog behavior.
12. **Schedule UI.** Lawyer creation prefills editable Mon–Fri 09:00–17:00, weekends off and 30 minutes. Edit includes seven working toggles, start/end inputs, duration validation and Save Schedule. Backend callers omitting a schedule receive off days. Time strings normalize to `HH:mm:ss` for .NET; date-only values stay strings.
13. **Leave UI.** Upcoming leave list, add/edit/delete, partial/multi-day dates and times, free-text reason and Full Day. The full-day end date is inclusive in the UI and becomes exclusive next-day midnight in the API. Forms use white surfaces, navy text and orange actions; inspected at 390 and 1280 pixels against mocked and real APIs.
14. **Conflicts.** Schedule and leave management enforce Admin authorization on the backend. Leave conflicts return 409 with IDs/date/start/end; the form retains entered values and displays the conflicting appointments and resolution instruction. Schedule edits cannot strand existing future appointments. Booking/rescheduling and recommendation approval revalidate inside transactions with a common lawyer-row lock. Stale selection returns 409. Date changes clear old choices and delayed responses cannot replace the new date's times. No automatic cancellation or rescheduling was added.
